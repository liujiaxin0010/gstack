# 预着陆审查清单

## 两遍审查结构

### 第一遍：关键问题（CRITICAL）

**1. SQL 与数据安全**
- 原始 SQL 拼接（注入风险）
- 缺少事务的多步数据变更
- 未索引的新查询
- 批量删除/更新缺少 WHERE 限制
- 数据库迁移的向后兼容性

**2. 竞态条件与并发**
- 非原子的"读-改-写"模式
- 缺少乐观锁的状态转换
- 共享资源无互斥保护
- 后台任务的幂等性

**3. LLM 输出信任边界**
- LLM 返回的内容直接写入数据库（缺少验证）
- LLM 输出用于构造 SQL/命令/文件路径
- 缺少对 LLM 幻觉/拒绝/空输出/畸形 JSON 的处理
- 用户输入直接注入 prompt（提示注入风险）

**4. 枚举与值完整性**
- 新增枚举值但 switch/case 未覆盖
- 新增状态但状态机未处理
- 新增类型但序列化/反序列化未更新
- **注意：此类问题需要读取 diff 之外的代码。** 用 Grep 查找引用兄弟值的所有文件，然后 Read 这些文件检查新值是否被处理。

### 第二遍：信息性问题（INFORMATIONAL）

1. **条件副作用** — if/else 分支中隐藏的副作用（发邮件、写日志、触发 webhook）
2. **魔数与字符串耦合** — 硬编码的数字或字符串应提取为常量
3. **死代码与一致性** — 未使用的导入、不可达代码、命名不一致
4. **LLM Prompt 问题** — prompt 过长、缺少示例、温度设置不当
5. **测试缺口** — 新功能路径缺少测试、只测了 happy path
6. **前端/视图问题** — XSS 风险、缺少 CSRF、无障碍问题、性能问题
7. **文档过时** — 代码变了但文档没更新
8. **安全问题** — 硬编码密钥、过于宽松的权限、缺少输入验证

## Fix-First 启发式

对每个发现进行分类：

### AUTO-FIX（机械性修复，直接执行）
- 未使用的导入/变量
- 缺少分号/格式问题
- 简单的类型注解缺失
- 明显的拼写错误
- CSS `outline: none` 没有替代焦点样式
- `!important` 覆盖（可以用更具体的选择器替代）

### ASK（需要判断，询问 Boss）
- 架构变更
- API 契约变更
- 性能优化（可能改变行为）
- 安全相关修复
- 数据库 schema 变更
- 任何可能影响其他功能的修复

## 严重性分类

| 级别 | 标签 | 含义 |
|------|------|------|
| 🔴 | CRITICAL | 功能错误、安全漏洞、数据丢失风险 → 必须修复 |
| 🟡 | WARNING | 代码异味、可维护性差、性能隐患 → 应该修复 |
| 🔵 | INFO | 更好的命名、更优的模式 → 考虑改进 |

## 抑制列表（不标记）

以下模式在审查中**不要标记**：
- 测试文件中的硬编码值（测试 fixtures 是合理的）
- 配置文件中的数字常量（端口号、超时等，通常是合理的默认值）
- CHANGELOG/README 中的格式问题（这些由 /document-release 处理）
- `console.log` 如果它是一个 CLI 工具（CLI 的输出就是 console.log）

## 输出格式

```
预着陆审查：N 个问题（X 个关键，Y 个信息性）

[AUTO-FIXED] file:line 问题 → 修复内容
[AUTO-FIXED] file:line 问题 → 修复内容

需要 Boss 确认的问题：
1. [CRITICAL] file:line — 问题描述
   修复建议：...
   → A) 修复  B) 跳过

2. [INFO] file:line — 问题描述
   修复建议：...
   → A) 修复  B) 跳过

推荐：两个都修——#1 是真正的竞态条件，#2 防止静默数据损坏。
```
